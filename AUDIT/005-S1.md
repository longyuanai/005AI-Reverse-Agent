## 通过项亮点

### ARCH-001 — 6 架构真支持
- `Architecture` enum: X86 / X64 / ARM / AARCH64 / MIPS / RISCV ✅ 与 STAGES.md 完全一致
- **完整别名系统** (`_ALIASES`): `i386/i486/i586/i686/ia32`、`x64/x8664/amd64`、`arm/arm32`、`aarch64/arm64`、`mips/mips32/mips64`、`riscv/riscv32/riscv64`——接受工具链输出的人话写法
- **PE Machine ID 映射**: 完整 `_PE_MACHINE_SPECS` 含 IMAGE_FILE_MACHINE_I386 / AMD64 / ARM / THUMB / ARMNT / ARM64 / R3000 / R4000 / R10000 / WCEMIPSV2 / MIPS16 / MIPSFPU / MIPSFPU16 / RISCV32 / RISCV64,共 15 个 PE machine type
- **ELF Machine 映射**: 6 个架构全有 (EM_386/EM_MIPS/EM_ARM/EM_X86_64/EM_AARCH64/EM_RISCV)
- **架构×位宽×字节序校验**: `__post_init__` 自动拒绝 `X86/BIG` 或 `RISC-V/BIG` 这种非法组合(避免底层 Capstone 抛莫名错)
- MIPS 支持 32/64 位双位宽

### DISASM-001 — Capstone 真接入
- `disassemble_bytes(data, architecture, *, bits, endianness, base_address, thumb, max_instructions, strict)`:
  - Capstone `Cs(capstone_arch, capstone_mode)` + `engine.disasm(...)` 真解码
  - ARM Thumb 模式强制 `architecture == ARM`(否则抛 `ValueError`)
  - RISC-V 压缩指令自动接受
  - 返回 `DisassemblyResult`: 解码指令数 + 未消费尾部字节 + 是否截断
  - `strict=True` 时未消费尾部触发 `DisassemblyError`
- `DisassemblyError(ValueError)` 子类化,异常类型清晰
- 输入校验:`base_address >= 0`、`max_instructions >= 1`(顶层契约)
