# 005 AI-Reverse-Agent 商用准备与验收规范

> 状态：提议 / 待产品负责人批准
> 版本：1.0
> 日期：2026-08-01
> 适用对象：产品、研发、安全、测试、交付和运维

## 1. 文档目的

本文件把“核心算法能运行”转换为“产品可安全交付、可运维、可审计、可回滚”的
验收标准。现有 278 项测试是研发基线，不等于商用认证。

商用交付分为三个门禁：

- **Commercial Alpha**：工程架构可持续，能在受控环境完成真实语料评测。
- **Private Pilot**：可交付给少量授权客户，具备 UI、认证、隔离、审计和离线部署。
- **Commercial GA**：达到发布、可用性、升级、恢复、支持和合规要求。

## 2. 支持与非支持矩阵

### 2.1 承诺支持

| 类别 | 支持范围 |
|------|----------|
| 文件 | PE、ELF、raw binary，单文件默认 ≤ 100 MiB |
| 架构 | x86、x64、ARM、AArch64、MIPS、RISC-V |
| 分析 | 静态解析、反汇编、轻量伪 C、CFG、import/IAT、规则与字符串分析 |
| 检测 | 加密常量、轻量混淆、双 import hash、本地恶意 hash、YARA 生成 |
| 工作流 | CLI、版本化 API、异步扫描、结果导出、人工复核 |
| 部署 | Windows/Linux 单机与私有化；默认离线分析 |

### 2.2 明确不承诺

- 不执行、调试或动态引爆样本。
- 不保证恢复原始源码、变量名或精确类型。
- 不自动绕过 DRM、许可证、VM 保护或复杂商业壳。
- 不提供未授权目标分析、攻击自动化或 0day 发现承诺。
- Mach-O、WebAssembly、固件拆包和移动端专用格式需另立 issue。
- LLM 输出是建议，不能单独构成 HIGH/CRITICAL 安全结论。

## 3. 目标用户工作流

1. 用户声明已获授权并上传样本，系统计算 SHA-256、识别格式并进行配额检查。
2. API 创建不可变 job，返回 job ID；worker 在受限环境执行静态分析。
3. UI 展示排队、运行、降级、失败、完成和取消状态，不伪造进度。
4. 结果按文件、函数、基本块和指令组织，Finding 可跳转到原始证据。
5. LLM 仅在策略允许时接收最小必要上下文，输出带模型、证据和置信度。
6. 分析师确认、驳回或修订 Finding；所有动作写入不可抵赖审计记录。
7. 用户导出 JSON/Markdown/PDF；删除操作遵循保留策略并可验证。

## 4. 生产组件

| 组件 | 职责 | 失败策略 |
|------|------|----------|
| Web UI | 上传、进度、结果、复核、导出 | API 不可用时明确降级，不缓存敏感正文 |
| Gateway/API | 认证、授权、限流、契约、job API | 快速失败，不在请求线程分析大文件 |
| Queue | 持久任务、重试、取消、租约 | 幂等重试，死信队列，不重复发布结果 |
| Static worker | 受限静态分析 | 超时/内存/磁盘上限，进程崩溃隔离 |
| Metadata DB | job、Finding、用户、审计、配置 | 迁移、备份、恢复、租户边界 |
| Object storage | 样本、报告、图像 | 加密、生命周期、完整性校验 |
| LLM gateway | 模型路由、脱敏、预算、审计 | 默认关闭外发，失败不阻塞纯静态结果 |
| Optional adapters | Ghidra/capa/FLOSS 等 | capability 检测，缺失时结构化降级 |

具体选型按需通过 ADR 审批；不得在实现阶段静默加入生产依赖。

## 5. 威胁模型

### 5.1 主要资产

- 客户二进制、符号、字符串、反编译结果和报告。
- 用户身份、权限、审计记录和 API 凭据。
- 规则库、恶意 hash 数据库、模型提示和产品知识产权。

### 5.2 主要威胁

| 威胁 | 典型入口 | 必要控制 |
|------|----------|----------|
| 解析器崩溃/资源耗尽 | 畸形 PE/ELF、超大 CFG、字符串炸弹 | 多级配额、超时、worker 隔离、fuzz/regression corpus |
| 样本意外执行 | 外部工具、错误的预览器或 shell | 永不执行样本、参数数组、最小权限、no-network worker |
| 跨租户泄露 | 缓存、对象路径、日志、数据库查询 | tenant ID 强制过滤、对象前缀、授权测试、日志脱敏 |
| LLM 数据外泄 | 云模型请求、提示日志 | 默认离线、显式策略、最小上下文、审计和禁传字段 |
| 供应链攻击 | PyPI/npm/容器/构建机 | lock、hash、SBOM、签名、依赖与许可证扫描 |
| 规则误报 | fixture 污染、弱 hash、LLM 幻觉 | provenance、clean corpus、人工 gate、可回滚规则版本 |
| 凭据泄露 | 配置、CLI、日志、错误堆栈 | secret manager、屏蔽、轮换、secret scan |

## 6. 数据与隐私

- 每个租户配置上传、结果、日志和备份保留期；默认最小保留。
- 删除必须覆盖主存储和后续备份生命周期，并产生审计事件。
- 原始样本不得进入普通应用日志、错误追踪或产品分析 telemetry。
- 外发 LLM 必须展示 provider、区域、数据保留策略和用户授权状态。
- 样本、报告和数据库备份使用独立密钥域；密钥轮换不需要重加密停机。
- 测试仓库只允许可再生成 fixture、公开授权样本或明确的合成数据。

## 7. 质量评测协议

### 7.1 数据集

- clean corpus：至少 1,000 个合法样本，覆盖编译器、架构和格式。
- detection corpus：至少 500 个经授权且带标签的样本。
- malformed corpus：至少 500 个截断、畸形、极限和历史崩溃样本。
- performance corpus：1/10/50/100 MiB 分层，记录压缩率、函数数和 CFG 规模。

样本清单记录来源、许可证/授权、SHA-256、标签依据和是否允许入仓；敏感样本只保存
manifest，不提交二进制。

### 7.2 指标

- 解析成功率、结构化失败率、崩溃率、超时率和峰值内存。
- 每条规则的 precision、recall、F1 和架构分层结果。
- HIGH Finding 的 clean-corpus 误报率。
- 函数边界、import、库函数和 CFG 与参考工具的差异。
- LLM 摘要由双人盲评：正确、证据充分、无臆造、可操作。
- 性能报告必须可复现，禁止只报告最好一次运行。

### 7.3 发布阻断

以下任一情况阻断发布：

- 支持格式存在可复现崩溃、越界资源使用或样本执行。
- 冻结 envelope 不兼容、迁移不可回滚或租户隔离失败。
- HIGH 误报率、检测召回率或性能未达到对应版本门禁。
- 发布物无法生成 SBOM/签名，或存在未豁免的 Critical/High 供应链漏洞。
- 关键结论缺少证据，或 LLM 结果被当作确定性事实。

## 8. 测试与 CI 门禁

每个 PR 至少执行适用项：

1. unit、contract、integration、CLI smoke。
2. Windows 与 Linux Python 支持矩阵。
3. 类型检查、格式、lint、SAST、secret 和依赖扫描。
4. parser fuzz/regression corpus；涉及解析器的变更必须跑。
5. UI lint、typecheck、component 和关键浏览器 E2E。
6. 容器/安装包构建、启动、升级和回滚 smoke。
7. 性能敏感变更与最近稳定版本对比，超过 10% 回退需审批。

失败检查不得通过修改门禁为可选来规避。环境型 skip 必须有原因、负责人和到期日。

## 9. 发布、升级与支持

- 使用 SemVer；发布分支从受保护主分支产生，tag 与制品签名。
- 生成 changelog、SBOM、依赖许可证清单、迁移说明和已知问题。
- 数据库和规则库分别版本化；规则回滚不依赖应用整体降级。
- GA 前完成空环境安装、上一版本升级、失败回滚和备份恢复演练。
- 定义支持版本、严重级别、响应时间和安全漏洞披露邮箱。
- 不自动上传客户样本；telemetry 默认关闭并能被管理员验证。

## 11. 商用发布签字

每个阶段需要以下角色签字；同一人可以兼任，但不得省略检查结果：

- 产品负责人：支持范围、非目标、定价版本和用户价值。
- 技术负责人：架构、迁移、依赖、性能和回滚。
- 安全负责人：威胁模型、隔离、审计、供应链和漏洞处置。
- 测试负责人：语料、自动化、回归、兼容性和发布证据。
- 交付/运维：安装、升级、备份、恢复、监控和支持手册。

未经签字的版本可以标记开发版或试点版，不得标记 Commercial GA。
